# Cosplayer — Audit

## Persona briefing

I'm a 4-time Dragon Con costume-contest winner specializing in technical builds — electroluminescent wire integration, custom resin-cast armor, and accurate silhouette matching with asymmetric prop placement. My judging matrix prioritizes: *Can I build this in 12 weeks? Are the reference images complete enough to resolve ambiguities in rib-cage width, shoulder seam geometry, and hair-fall asymmetry? Do I have hex codes for faction colors to match dyes? Are the 20+ paperdoll layers documented so I know which pieces are story-gated vs. craft-available?* Dischordian Saga's visual canon is fragmented across scattered character busts, expression sheets that don't include body geometry, and paperdoll slots with no flavor-text or faction-color guidance. These gaps force me to interpolate, losing the 3-month planning window I need.

1. **Turnarounds missing for 25 of 27 characters — only Elara & The Human have 360-degree geometry reference**
   - **Severity:** P0
   - **Where:** `apps/client/public/characters/_inventory.json:24–56` (Elara front_turnaround + full_turnaround; The Human front_turnaround + full_turnaround + reveal_start + reveal_end), lines 73–883 (all other NPCs: bust only, no turnarounds)
   - **What's wrong:** The inventory lists 27 character folders, but only two protagonists ship turnaround assets. A cosplayer studying Agent Zero, Shadow Tongue, or the Antiquarian cannot resolve silhouette depth, back-armor geometry, or cape/cloak fall — only face-on framing exists.
   - **Why it matters to this persona:** Turnaround sheets are non-negotiable for costume judgment. Dragon Con rubrics score "How closely does the silhouette match the source?" A missing turnaround means I'm guessing 50% of the costume. Asymmetric details (Shadow Tongue's slit pupils, the Antiquarian's beard thinning, the Warlord's rust-red beard mass) are documented *only* in mouthBox calibration notes inside `characterSprites.ts:267–369`; there's no canonical art to trace.
   - **Recommended fix:** Ship 360-degree turnarounds for all 18 NPC speakers (agent_zero, adjudicator_locke, the_antiquarian, the_source, shadow_tongue, the_meme, architect, collector, degen, eidola, engineer, enigma, eyes, gamemaster, iron_lion, kael_recruiter, matrikala, necromancer, nilmorg, programmer, seer, warlord, watcher) plus bonus characters. Add to `_inventory.json` as `${character}/front_turnaround.avif` and `${character}/full_turnaround.avif`. Store originals in `apps/client/public/characters/$id/`, rebuild manifests.

Reference `suitArtPrompts.ts:148–156` (ELEMENT_PALETTES) and 122–129 (RARITY_LABELS). Serve as JSON + HTML.

3. **Viseme-sheet composition logic buried in characterSprites.ts comments; mouth-box calibration opacity unclear**
   - **Severity:** P1
   - **Where:** `apps/client/src/game/characterSprites.ts:42–79` (MouthBox interface with x/y/width/height fractions), lines 165–191 (Elara example with bustSize "auto 220%", bustPosition "center 12%", mouthBox y=0.58), lines 231–280 (NPC mouthBox calibration)
   - **What's wrong:** Each NPC's mouth-only viseme is composited on top of the bust at a specific (x, y, width, height) bounding box — but the logic is scattered across inline comments, not documented. For example, Elara's mouthBox is `{ x: 0.40, y: 0.58, width: 0.20, height: 0.11 }` after `bustSize="auto 220%"` zoom + `position="center 12%"` shift. These fractions are calculated per-character and not explained in a single reference table. A cosplayer studying Elara's lip-sync would need to reverse-engineer the zoom factor to understand where her mouth actually sits on the costume.
   - **Why it matters to this persona:** If I'm building an Elara helmet or mask, I need to know: *Where does the mouth cavity sit as a percentage of total face height? Is it dead-center or offset?* The answer is in calibration notes but not accessible via asset metadata. The debug flag `?debug-mouthbox=1` exists (line 189) but is undocumented in public output.
   - **Recommended fix:** Export a `/characters/[id]/mouth-calibration.json` per NPC with `{ bustSize, bustPosition, mouthBox, description }`. Document the `?debug-mouthbox=1` flag in a public guide. Link from each character's turnaround page so cosplayers can verify mouth placement before committing to helmet geometry.

4. **Height-comparison band missing — no canonical height data or scale-to-reference grid**
   - **Severity:** P1
   - **Where:** `apps/client/public/characters/_inventory.json` (no height field), `apps/client/src/game/characterSprites.ts` (bust image dimensions are in pixels but no height/build metadata)
   - **What's wrong:** The `_inventory.json` lists width/height in pixels for each asset (e.g., elara idle_hologram 1792x2400), but these are *image canvas dimensions*, not character heights in-world. No metadata maps "Elara is 6'2" or "Minnie is 7 years old (3'6")" or relative scale (is Shadow Tongue taller than Agent Zero?). Character art brief references (§2A, §2N, §2K) exist in source comments (`characterSprites.ts:199–228` on Minnie's child-face per §2N) but are not exposed as structured data.
   - **Why it matters to this persona:** Dragon Con cosplay judging includes a height-comparison band — costumes are scored on how accurately they match the source character's frame. If I'm 5'10" and Elara is canonically 6'2", I need to platform my shoes or accept the height mismatch. If Minnie is a 7-year-old girl, I need to either shrink proportionally (impossible) or note the non-match. Currently I have no way to know.
   - **Recommended fix:** Add a metadata object to each character folder: `/characters/[id]/metadata.json { canonicalHeight: "6'2\"", buildType: "lithe athletic", ageApproximation: "adult", speciesApproximation: "humanoid" }`. Reference art-brief section numbers for traceability. Derive from narrative context if not explicitly stated.

5. **Blood Weave visual progression stages have lore descriptions but no associated art reference or color band**
   - **Severity:** P2
   - **Where:** `apps/shared/bloodWeave.ts:124–133` (BloodWeaveBand type; bandFor() function mapping alignment ranges to "dormant/braiding/woven/bound/claimed"), lines 61–80 (BLOOD_WEAVE_REVEAL_POOL with 12 threshold previews)
   - **What's wrong:** The Blood Weave is a cumulative alignment track that moves the player from "dormant" (alignment 0–5) → "braiding" → "woven" (5–15) → "bound" (15–30) → "claimed" (30+). Each band should have a visual signature (color, glow intensity, thread pattern) for UI and costume decoration. The code documents the narrative thresholds (threshold: 1 "The Hellbox hums afterwards", threshold: 9 "Who the Game Master is") but assigns no hex color or visual asset to each band. A cosplayer building a Blood Weave-inspired costume (increasingly elaborate red-thread embroidery as alignment progresses) has no visual canon to reference.
   - **Why it matters to this persona:** If Blood Weave is a major cosmetic track (like a progression-based armor-set glow or thread-embroidery effect), I need to know: *At "claimed" alignment, is the character glowing with red-thread veins? Are they visibly corrupted? What color temperature?* Currently only the narrative thresholds are defined; visual equivalents are missing.
   - **Recommended fix:** Extend `BLOOD_WEAVE_REVEAL_POOL` to include color + visual-cue metadata per band: `{ band: "braiding", colorHex: "#8b3a3a", glowIntensity: "subtle", threadDescription: "faint red tracery visible only in shadow light" }`. Create progression-gallery images showing costume/UI appearance at each band. Reference from Loredex entries.

6. **Expansion art manifests ship set IDs but no set-metadata association — "Hierarchy of the Damned" cards divorced from suit-piece catalog**
   - **Severity:** P2
   - **Where:** `apps/shared/expansionArt/hierarchyOfDamned.ts:56–181` (124 assetId entries indexed by rarity, no suitSetId cross-reference), `apps/shared/suitSets.ts` (getAllSetIds() returns 18 class/species/element/foundation sets; no "hierarchy-of-damned" set)

This is correct system design, but the boundary between expansion-art and wearable-gear is invisible to external tooling.
   - **Why it matters to this persona:** If Hierarchy of the Damned cards are *cosmetic cosmetics* (cosmetic weapon skins, cosmetic emotes, no armor), I'm looking at the wrong asset pipeline for costume reference. If they're *flavor art* for story moments, I need to know the narrative context ("CEO Mol Garath is the villain; here's her office aesthetic") to build thematically.    - **Recommended fix:** Add metadata to `hierarchyOfDamned.ts` entries: `{ assetId, cardType: "cosmetic" | "narrative-flavor" | "suit-art-inspiration", relatedSuitSetId?: string, description: "brief context" }`. Document in a public guide whether these are craftable items, narrative-context art, or out-of-game TCG card illustrations.
